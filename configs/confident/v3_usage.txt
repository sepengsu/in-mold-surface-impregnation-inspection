changed_v3 A/B/C/D 실행 안내

이번 코드 작성에서는 실제 학습, OOF, 모델 추론, calibration, sweep을 실행하지 않는다.
기존 v2 데이터/체크포인트/출력과 legacy C=사람 검수 라벨 조건은 보존한다.
새 C는 CL 후보의 loss weight=0.5이며 모든 B/C/D가 동일 common 후보를 사용한다.

PowerShell 공통:
  Set-Location D:\Code\vision_data
  $run = '.\src\Namrc\run_changed_v3.ps1'
  $exp = 'D:\Code\vision_data\analysis\confident\changed_v3_softweight_MY_RUN'

검증과 준비만 (학습 없음):
  & $run -Stage prepare -Output $exp
  & $run -Stage audit-plan -Experiment $exp

현재 strict Gold Case 제외는 eligible=0이다. audit/blocker.json을 기록한다.
Gold가 20개 Case를 모두 포함하므로 현재 Train에서 독립 Audit를 만들 수 없다.
새 독립 Case 자료 또는 사용자가 명시적으로 승인한 범위 예외가 필요하다.
이 제약 때문에 후보와 B/C/D를 근거 없이 자동 진행하는 all 단계는 제공하지 않는다.
예외가 나중에 승인된 경우에만 별도 JSON에 다음을 기록한다:
  approved: true
  allow_gold_case_overlap: true
  human_user_instruction: 실제 사용자 지시 전문
예외를 코드가 임의로 승인하거나 Gold 픽셀을 Audit GT로 사용하는 것은 금지한다.
예외에서도 동일 Gold 이미지는 제외하고 Dev/Check Case를 분리한다.
동일 Case Audit를 허용한 결과는 Gold와 완전히 독립적인 정책 검증이라고 부르지 않는다.

추후 학습/OOF 실행을 원할 때 사용자가 직접 실행할 명령 (이번 작업에서는 실행 안 함):

  & $run -Stage issues -Experiment $exp
  & $run -Stage audit-plan -Experiment $exp -AuditScopeAuthorization '승인된_범위_예외.json'

audit/review.template.json을 복사해 review.json을 만든다.

각 tile의 reviewed=true, reviewer, judged_before_cl_display=true,

타일 순서/선정 정보는 변경하지 않는다. 사람 마스크는 학습 target으로 쓰지 않는다.
60타일은 초기 표본안일 뿐 충분성을 보장하지 않는다. 층화 표본은 표본 결과로만 보고한다.

Dev에서 공통 방향 규칙을 정한다. v3_policy.template.json을 복사해

Check를 보기 전에 모든 규칙과 운영 목표를 고정한다. 양 방향 enabled=false는 0후보를 그대로 보고한다.

Case bootstrap을 사용하며 픽셀 독립성을 가정하지 않는다. 불확실 후보는 보수적 gate에서 실패로 센다.
