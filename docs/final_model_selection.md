# 함침율 산출용 모델 선택

최신 **테스트 MAPE 기준** 비교는 [테스트 MAPE 기준 모델 비교](test_mape_model_comparison.md)에 있다. B와 C까지 테스트한 결과 전체 타일은 C, 중앙 3개는 B의 MAPE가 가장 낮았다. 아래 내용은 그 이전의 검증 기준 후보 선정과 A 및 D 비교 기록이다.

2026년 10월 1일 완료된 개선 비교 결과를 확인했다. **000 방향 중앙 3개의 함침율을 산출하는 현재 목적에는 A baseline의 39 epoch 체크포인트를 우선 후보로 추천한다.** 전체 분할 Dice를 기준으로 자동 선정된 모델은 D combined의 57 epoch 체크포인트다. 두 선택은 평가 목적이 다르다.

## MAPE 기준 평가

함침율의 상대 오차를 주된 평가 대상으로 삼아 **검증 중앙 3개 타일의 MAPE를 우선 지표**로 둔다. MAE는 실제 함침율 차이를 나타내는 %p 단위의 보조 지표로 함께 기록한다. 저장된 예측으로 MAPE를 재계산해도 현재 후보는 A다.

`MAPE(%) = 100 × mean(abs(예측 함침율 − 정답 함침율) / abs(정답 함침율))`

각 타일의 상대 오차를 구한 다음 평균한다. MAE를 정답 함침율의 평균으로 나눈 값과는 다르다. 예를 들어 정답 함침율 95%, 예측 94%라면 MAE는 1%p, MAPE는 약 1.053%다. scikit-learn의 MAPE 함수는 백분율이 아닌 비율을 반환하므로, 그 함수를 사용한다면 결과에 100을 곱해야 한다. [공식 MAPE 문서](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.mean_absolute_percentage_error.html)

| 최신 조건 | 전체 검증 MAPE | 중앙 000 타일 검증 MAPE |
| --- | ---: | ---: |
| A 기본 | **0.7548%** | **0.6010%** |
| B 큰 영역 가중 추출 | 0.8001% | 0.6053% |
| C Tversky | 0.7992% | 0.6346% |
| D 두 방법 결합 | 0.7727% | 0.7171% |

| 테스트 범위 | 최신 A MAPE | 최신 D MAPE |
| --- | ---: | ---: |
| 전체 197장 | **1.3952%** | 1.3983% |
| 중앙 000 타일 27장 | **0.7727%** | 0.9184% |

전체 검증의 정답 함침율은 약 59.935%부터 99.893%, 테스트는 62.463%부터 99.330%로 0 분모가 없다. 정답이 0에 가까우면 MAPE가 크게 증폭될 수 있는데, 이번 자료는 이에 해당하지 않는다. 0인 정답을 제외하거나 분모에 epsilon을 넣어 계산하지 않았다. [공식 문서의 0 부근 동작 설명](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.mean_absolute_percentage_error.html)

이 지표의 분모는 함침율이며, Exposure인 미함침율이 아니다. 정답 함침율 98%, 예측 97%는 함침율 MAPE로 약 1.020%지만, 미함침율 2%를 3%로 예측한 상대 오차는 50%다. 따라서 작은 함침율 MAPE만으로 미함침 영역을 정확히 분할했다고 판단할 수는 없고, Dice와 IoU도 함께 본다.

이번 계산은 **이미 검증 Dice로 저장한 best.pt들의 MAPE 비교**다. 모든 epoch 중 MAPE가 가장 낮은 체크포인트를 새로 선정한 것은 아니다. 기존 학습과 비교 프로그램의 자동 저장 및 선정 기준도 여전히 Dice이며, 이후 MAPE 기준 학습을 하려면 epoch별 MAPE 기록과 최소 MAPE 체크포인트 저장을 구현해야 한다. 아래 MAE 분석과 추가 테스트 이전 선택 기록은 당시의 계산 근거로 보존한다.

## 최신 비교 결과

대상 실행은 `comparison_improvement_20261001_053043_365`이며 네 조건 모두 완료됐다. 학습 1,101장, 검증 208장, 테스트 197장을 사용했고, 네 조건과 이전 비교의 case 분할 해시가 모두 일치한다. 최대 500 epoch로 실행했으나 실제 종료는 A 59, B 81, C 65, D 77 epoch였다.

| 조건 | 최적 epoch | 전체 검증 Dice | 전체 검증 함침율 MAE | 중앙 3개 검증 함침율 MAE |
| --- | ---: | ---: | ---: | ---: |
| A 기본 | 39 | 0.909638 | **0.6893%p** | **0.5783%p** |
| B 큰 영역 가중 추출 | 61 | 0.910695 | 0.7213%p | 0.5817%p |
| C Tversky | 45 | 0.907784 | 0.7324%p | 0.6120%p |
| D 두 방법 결합 | 57 | **0.911194** | 0.7139%p | 0.6914%p |

중앙 3개 검증 평가는 000 방향 9개 촬영 이미지에서 P1, P2, P3를 추출한 27개 타일이다. 원본 2046 × 2046 좌표에서 타일 시작점은 `(639,895)`, `(895,895)`, `(1151,895)`다. 검증 case는 3개뿐이다.

D는 A보다 전체 검증 Dice가 0.00156 높고 큰 영역 검증 타일의 Dice도 더 높다. 하지만 A는 전체 및 중앙 타일 함침율 오차가 더 낮다. A와 B의 중앙 MAE 차이는 0.00345%p에 불과하므로, A가 다른 seed와 새로운 시편에서도 항상 우수하다고 단정할 수는 없다. 현재 목적의 검증 지표와 구현의 단순성을 고려하면 A부터 사용하는 것이 합리적이다.

## 검증 기준으로 후보를 정한 뒤 확인한 테스트 결과

원래 비교 프로그램은 D만 테스트했다. 이번 검토에서는 중앙 3개 검증 MAE를 우선 기준으로 A를 선택한 기록을 먼저 저장한 뒤, A의 기존 체크포인트로 테스트 197장을 추가 추론했다. 테스트 결과를 보고 A와 D 중 후보를 바꾸지 않았다. 다만 평가 목적에 맞춘 기준 변경은 원래 자동 비교 이후의 분석이며, 이 테스트의 오류는 이전부터 방법 개발에 참고했다. 독립적인 최종 확인에는 새 case가 필요하다.

| 테스트 항목 | 최신 A | 최신 D |
| --- | ---: | ---: |
| 전체 197장 Dice | 0.8350 | **0.8387** |
| 전체 197장 IoU | 0.7168 | **0.7223** |
| 전체 함침율 MAE | **1.227%p** | 1.237%p |
| 중앙 000 타일 27장 Dice | **0.8558** | 0.8446 |
| 중앙 타일 함침율 MAE | **0.752%p** | 0.895%p |
| 중앙 타일 최대 절대 오차 | **2.023%p** | 2.284%p |
| 중앙 타일 절대 오차 2%p 이하 | 26 / 27 | 26 / 27 |
| P1 P2 P3 평균의 함침율 MAE | **0.555%p** | 0.743%p |
| 전체 타일 최대 절대 오차 | 19.102%p | **17.459%p** |

평균 함침율 지표는 9개 촬영별 P1, P2, P3 평균을 정답 평균과 비교한 값이다. P1, P2, P3 각각을 엑셀에 넣는 목적에는 개별 타일 MAE인 0.752%p를 보고해야 한다. 평균을 사용해서 개별 위치의 오차가 작아졌다고 해석하면 안 된다.

이전 비교의 A와 최신 D를 전체 테스트로 비교해도 Dice는 0.8381에서 0.8387로 조금 증가하고 함침율 MAE는 1.205%p에서 1.237%p로 증가했다. 새 방법이 실사용 정확도를 크게 높였다는 결과는 아니다. 최신 A 역시 중앙 위치에서는 유용한 후보지만, 전체 영역에서는 큰 미함침 누락과 19%p 수준의 최대 오차가 남아 있다.

## 지금 사용할 체크포인트

사용 후보는 다음 파일이다. 마지막 epoch를 저장하는 `last.pt` 대신 검증 최적 epoch의 `best.pt`를 사용한다.

`D:\Code\vision_data\outputs\training\comparison_improvement_20261001_053043_365\A_baseline\best.pt`

- 모델: 회색조 U-Net, base channels 32
- 학습: basic 회전과 반전, 균등 순회, BCE + Dice
- epoch: 39
- 학습 seed: 42, 분할 seed: 42
- 입력: 리사이즈하지 않은 256 × 256 uint8 회색조, 정규화 `x / 255`
- 확률 임계값: 0.5 유지
- 함침율: `100 × (1 − 예측 Exposure 픽셀 수 / 65,536)`
- 체크포인트 SHA256: `092a9d33c76b95b000041aadcf82347eeea0c929dab293f84442ce6041c57cb6`

현재 자동 선택 파일 `selected_model.json`은 원래 기준에 따라 D를 가리키며, 이번 분석에서 이를 수정하지 않았다. 이 때문에 최신 모델 자동 탐색에 맡기지 않고 아래처럼 A를 명시한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "D:\Code\vision_data\src\inference\run_inference.ps1" `
  -Checkpoint "D:\Code\vision_data\outputs\training\comparison_improvement_20261001_053043_365\A_baseline\best.pt" `
  -Split test -Position 000 -Threshold 0.5 -Open
```

이 명령은 테스트 split의 000 방향 타일 전체를 시각화한다. 중앙 3개만 필터하는 옵션은 아니다. 중앙 지표는 앞서 명시한 좌표로 결과를 추출하여 집계했다. 이미 생성한 A의 전체 테스트 결과는 아래 산출물 링크에서 확인할 수 있다.

## 최종 확정 순서

1. 현재 A 체크포인트를 함침율 산출용 후보로 보존한다. 별도 배포 폴더를 만들 때 `best.pt`, `config.json`, `splits.json`, 설정과 해시 기록을 함께 보존한다. 체크포인트 이름만 바꾸는 것으로 전처리와 분할 정보가 보존되지는 않는다.
2. 재현성을 더 확인하려면 split seed 42를 유지하고 학습 seed 43, 44로 **같은 A 설정**을 반복한다. 후보 선택은 검증 중앙 3개의 개별 함침율 MAPE를 우선하고, MAE와 Dice 및 case별 오차를 함께 확인한다. epoch 선택까지 MAPE에 맞추려면 위에 설명한 저장 기준 변경이 선행되어야 한다. 테스트 점수가 가장 좋은 seed를 고르는 방식은 사용하지 않는다.
3. 최종 후보를 고정한 뒤 새로운 case에서 000 방향 중앙 3개를 측정하고, 실제 사용자가 정한 허용 오차와 대조한다. 현재 데이터의 2%p 이하 26/27은 관측 결과이며 허용 기준이나 앞으로의 정확도 보장이 아니다.
4. 최종 P1 P2 P3는 000 방향의 왼쪽, 중앙, 오른쪽 순서로 출력하고 기존 `매칭.xlsx` 기준으로 행을 연결한다. 학습에 포함된 시편의 재추론 결과는 모델 적용 결과이며 새로운 일반화 성능 평가와 구분한다.

최대 epoch를 더 늘리거나 모든 데이터를 합쳐 다시 학습한다고 더 좋은 최종본이 되는 것은 아니다. 전체 데이터 재학습을 한다면 기존 테스트 점수를 새 모델의 성능으로 표시할 수 없으며, 새로 고정한 평가 자료가 필요하다.
